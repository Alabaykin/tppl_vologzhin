# Выбор парадигм и языков программирования

## Задача 1. Обработка больших данных в реальном времени

* **Парадигма:** Data-Oriented Design (системное / обобщенное программирование).
* **Язык программирования:** C++.
* **Обоснование:**
  * **Огромный трафик данных:** Поток 100 кадров 4K (16 бит) — это больше 3 ГБ данных в секунду. C++ позволяет держать данные в памяти подряд без оверхеда, активно используя кэш процессора и SIMD-векторизацию для математических проверок.
  * **Никаких зависаний 24/7:** Любой сборщик мусора (GC) здесь гарантированно забьет буфер паузами и уронит кадры. На C++ память выделяется один раз при старте, исключая задержки в рантайме.
  * **Прямой выход на GPU:** Если расчетов на процессоре не хватит, код на C++ проще всего связать с видеокартой через CUDA или Vulkan.

## Задача 2. Прототип ML-сервиса для прогноза погодных условий

* **Парадигма:** Скриптовая (мультипарадигменный подход: ООП + функциональные элементы).
* **Язык программирования:** Python.
* **Обоснование:**
  * **Скорость сборки MVP:** Срок в 2 недели не оставляет времени на компиляцию и сложную архитектуру. На Python работающий прототип пишется быстрее всего.
  * **Готовые инструменты:** Вся метеорология и работа с датчиками закрываются стандартным стеком (pandas, numpy, scikit-learn, XGBoost) — изобретать велосипеды с нуля не нужно.
  * **Низкая частота запусков:** Прогноз считается всего раз в сутки, поэтому скорость самого интерпретатора не играет роли, а тяжелые вычисления внутри библиотек и так написаны на Си.
  * **Быстрые эксперименты:** Менять признаки и алгоритмы можно на ходу прямо в Jupyter Notebook.

## Задача 3. Интерактивный UI для торгового терминала

* **Парадигма:** Реактивная и компонентно-декларативная.
* **Язык программирования:** TypeScript.
* **Обоснование:**
  * **Связка потоков данных:** Тики из WebSocket и события от 50+ виджетов удобно описывать через реактивные потоки (RxJS, Signals). Изменение одной цены само обновит нужные графики без путаницы с ручными подписками.
  * **Плавные 60 FPS (< 16 мс):** Декларативные библиотеки перерисовывают только конкретные цифры в DOM-дереве, не перегружая браузер перерисовкой всего терминала.
  * **Защита от опечаток:** Торговые данные не прощают ошибок. Строгая типизация TS страхует от битых контрактов и неопределенных полей еще на этапе сборки.
  * **Удобные тесты:** Расчеты цен и логику обновления виджетов легко покрыть быстрыми юнит-тестами без запуска браузера.

## Задача 4. Прошивка для устройства регистрации температуры

* **Парадигма:** Процедурная (структурная).
* **Язык программирования:** C.
* **Обоснование:**
  * **Скромное железо (32 КБ RAM / 256 КБ Flash):** Чистый Си генерирует крошечный бинарник и не тащит за собой тяжелый рантайм, экономя каждый килобайт памяти.
  * **Экономия батарейки:** Код компилируется напрямую в машинные инструкции без скрытых затрат. Датчик мгновенно просыпается по прерыванию, опрашивает АЦП и сразу уходит обратно в глубокий сон (Deep Sleep).
  * **Прямая работа с регистрами:** Си позволяет обращаться к портам ввода-вывода (GPIO, ADC, UART) напрямую через адреса памяти и указатели.
  * **Переносимость:** Логика вычислений легко отделяется от аппаратной части через HAL (слой абстракции). При смене микроконтроллера достаточно переписать только функции чтения регистров.
